# Agent Note: 会话永久删除

Status: implemented

[English](2026-08-21-session-permanent-delete.md) | 中文

## 问题

会话可以归档、恢复，却从未能移除：栈中任何一层都没有删除。workspace 注册删除的 note 记录了这一边界（「注册删除不能替代会话删除」），侧边栏的已知限制也如此声明；持有敏感或垃圾对话的用户毫无办法——日志永远留在磁盘上。

## 决策

删除作为一个经确认的手势贯穿它触及的每一层：

- **持久化层**拥有移除。`SessionPersistence.delete(id)` 移除日志与该 id 在后端的全部工件——JSONL 后端移除会话目录，SQLite 在一个事务内删除行与其事件——并应答是否存在过任何东西。协调器针对该 id 的所有操作串行化、拒绝活跃会话（`cannot delete ... while it is live`）、在介质写入前等待进行中的释放收尾——且在该 id 的串行化链之外等待，因为收尾自身在 flush 之后才加入这条链，链内等待会让移除排在它所等待的收尾之前、互相死锁——写入后丢弃簿记与缓存的 preparation，并发出 `session/persistence-removed`。删除是唯一非追加写的操作；它之所以是独立操作而非日志变更，正是因为其余一切的 append-only 不变量保持完好。
- **网关**把这一手势组合在 `session.delete` 之后：运行中的轮次拒绝（`agent-busy`）；释放能力不在本网关手中的活跃 Agent 一律拒绝（能力由所有者持有，外来活跃会话与会话后端 subagent 都轮不到我们停止）；在触碰任何东西之前用活跃加持久两个来源做存在性门控；随后 dispose → persistence.delete → `workspaceRegistry.forgetSession`（记账席位 + 归档集合条目）。本网关铸出的每个句柄都落入同一张保留句柄映射——ensureSession 的创建与恢复、共享 Agent 解析器的冷恢复皆然（`ApiRemoteAgentOptions.retain`）——因为 `session.models` 这类通用入口会让冷会话变活却从不留下任何其他所有者；没有保留句柄的活跃身份按构造即不可删除。客户端无论哪种路径都经由普通的移除帧得知：被释放的活跃会话走 `session/disposed`，仅持久化的会话由 `persistence-removed` 转成同一帧形。
- **UI** 把破坏性与免确认分开：Archive/Unarchive 只移动可见性所以直接提交，而 Delete 采用与 workspace 注册删除相同的浏览器持有确认对话框模式，点名该会话并说明日志一并消失。普通行与「归档」区行都携带它。

## 已考虑的替代方案

**软删除／带宽限期的回收站。** 在归档之外再加一种可见性状态，外加尚无人需要的定时过期机制。归档集合已经覆盖「隐藏但可恢复」；永久删除的存在恰恰是为覆盖其不够用的时刻。

**面向活跃会话的注册表级 dispose 接口。** 扩宽 `AgentRegistry` 让任意调用者都能停止任意活跃 Agent 会破坏 handle-as-capability 纪律。网关保留它自己创建的 Agent 的句柄——这是它本就持有的所有权——对其余一切拒绝。

**仅客户端乐观移除、不发主机帧。** 其他标签页会继续显示已删除的对话直到重连。把仅持久化的删除接到既有 `host/session-removed` 帧上，让每个客户端走与活跃释放完全相同的移除路径。

## 后果

被删除的 id 同时从一切处消失：列表、搜索索引（从持久化观察重建）、workspace 分组、归档区和磁盘。孤边按设计保留且不可见：被删父会话的 subagent 子会话保留日志但无处渲染，仅被已删日志引用的附件 blob 等待未来的垃圾回收，投影缓存今天不为冷 id 驱逐（被删 id 的行变为不可达）。网关句柄映射是进程内的：主机重启后每个持久化会话都是冷的、可删除的——这也是常见情形。

## 测试

后端套件为两个物理后端钉住有序移除、活跃拒绝、未知 id 缺席、事件发出与跨重启持久性。网关 spec 经由协调器-backed 的 map 介质驱动活跃释放——包括经保留句柄由共享解析器弄活的会话——仅持久化删除、两种 busy 拒绝、not-found 分支以及移除帧。组件测试覆盖对话框门控（取消不提交、确认只调用一次、失败保持对话框打开）与两处菜单。`apps/web/tests/workspace-management.e2e.ts` fork 种子会话并在真实 wire 上删除：先取消再确认，断言该行、其新日志 id 与全部注册表事实一并消失。
